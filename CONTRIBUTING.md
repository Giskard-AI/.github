# Contributing

Thanks for helping improve a Giskard project. This guide applies to every Giskard-AI repository that does not have its own `CONTRIBUTING.md`.

1. Open an issue first for anything larger than a small fix, so we can agree on the approach.
2. Fork the repository (or create a branch if you have write access) and work on a dedicated branch.
3. Add or update tests for your change, and update the documentation when behavior changes.
4. Open a pull request with a [Conventional Commits](https://www.conventionalcommits.org/) title, for example `feat: add CSV export` or `fix: handle empty responses`.
5. Make sure CI passes. A maintainer reviews the pull request before it is merged.

Never commit secrets, credentials, or private data.

Security issues: do not open a public issue or pull request. Follow the repository's security policy (**Security** tab) or the [Giskard-AI security policy](https://github.com/Giskard-AI/.github/blob/main/SECURITY.md) instead.
